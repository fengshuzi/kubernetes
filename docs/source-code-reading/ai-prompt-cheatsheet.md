# AI提问快速参考卡

## 🚀 快速模板 (复制即用)

### 🔍 代码分析模板
```
我是10年Java开发者，正在学习K8s源码。

请分析以下代码：
```go
[粘贴代码]
```

文件：[路径:行号]
困惑：[具体问题]
期望：逐行解释+Java对比+Go语法说明
```

### 🏗️ 架构理解模板
```
Java架构师视角，请解释K8s的[组件/概念]：

对比场景：
- Java概念：[Spring/微服务相关]
- K8s概念：[对应概念]

期望：交互流程+设计思想+代码位置
```

### 🛠️ 开发实战模板
```
Java开发者开发K8s Controller遇到问题：

需求：[具体功能]
现状：[已完成部分]
问题：[具体困难]
代码：[相关代码片段]

期望：完整示例+最佳实践+Java对比
```

### 🐛 问题诊断模板
```
K8s源码调试问题：

环境：K8s v[版本] + Go [版本]
现象：[错误信息/异常行为]
代码：[问题代码]
已试：[尝试过的方案]

求助：根因分析+解决方案+预防措施
```

## ⚡ 一句话提问

### 代码理解
```
用Java开发者能理解的方式解释这段K8s代码：[代码]
```

### 概念对比
```
K8s的[概念]相当于Java的什么？详细对比分析
```

### 实现原理
```
从Spring框架角度，解释K8s的[机制]是如何实现的？
```

### 开发指导
```
Java开发者如何实现K8s的[功能]？提供完整代码示例
```

### 性能优化
```
K8s [组件]性能问题分析，对比Java应用调优方法
```

## 🎯 关键词提升效果

### 身份标识
- "10年Java开发经验"
- "熟悉Spring框架"
- "微服务架构师"
- "分布式系统专家"

### 对比需求
- "对比Java的[概念]"
- "类似Spring的[机制]"
- "与微服务架构的异同"
- "GoF设计模式角度"

### 回答要求
- "逐行解释代码"
- "提供可运行示例"
- "详细注释说明"
- "最佳实践建议"

### 深度层次
- "概念理解层面"
- "实现原理分析"
- "源码深度剖析"
- "生产实践指导"

## 📋 常用场景清单

### ✅ 适合AI回答的问题
- [ ] 代码逻辑解释
- [ ] 设计模式识别
- [ ] 架构原理分析
- [ ] 实现方案对比
- [ ] 最佳实践建议
- [ ] 学习路径规划

### ❌ 不适合AI的问题
- [ ] 实时集群状态查询
- [ ] 特定环境配置问题
- [ ] 商业决策建议
- [ ] 版本兼容性细节
- [ ] 社区政治问题

## 🔧 提问质量自检

### 问题清晰度 ⭐⭐⭐⭐⭐
- [ ] 有明确的技术背景说明
- [ ] 问题描述具体不模糊
- [ ] 提供了足够的上下文
- [ ] 期望回答格式明确

### 技术深度 ⭐⭐⭐⭐⭐
- [ ] 不是简单的概念查询
- [ ] 涉及具体的代码分析
- [ ] 需要深层次的理解
- [ ] 有实际应用价值

### 学习效果 ⭐⭐⭐⭐⭐
- [ ] 能解决当前的困惑
- [ ] 有助于知识体系构建
- [ ] 可以指导后续学习
- [ ] 便于对比记忆

## 💡 进阶技巧

### 🔄 迭代提问法
```
第1轮：概念理解
第2轮：实现细节
第3轮：应用实践
第4轮：性能优化
```

### 🎯 角色扮演法
```
"假设你是K8s的架构师，向Java团队解释..."
"作为code reviewer，分析这段代码的问题..."
"从运维角度，这种设计有什么优势？"
```

### 📊 对比学习法
```
并列对比：K8s实现 vs Java实现
演进对比：传统方式 vs K8s方式  
场景对比：开发环境 vs 生产环境
```

---

**记住：好的问题 = 明确的背景 + 具体的困惑 + 清晰的期望** 🎯
